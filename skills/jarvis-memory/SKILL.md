# Jarvis 本地知识与长期记忆

本技能把服务器工作区中的 Markdown 文档作为 Jarvis 的私有知识库。知识
不会因为 ChatGPT OAuth 登录而自动同步，也不要假设 ChatGPT 网页版记忆
已经存在于当前环境。

## 什么时候必须检索

回答以下问题前，先检索再作答：

- 用户身份、称呼、偏好、工作方式和表达风格；
- 历史项目、会议、决策、制度、架构和实施计划；
- “以前说过什么”“上次怎么定的”“按我的习惯”等连续性问题；
- 企业架构、数据架构、AI 架构、用增平台、万佛和数据流通；
- PPT、周报、纪要、邮件和管理汇报的既定标准。

## 检索步骤

1. 确认当前工作目录是 Jarvis workspace。
2. 从用户问题中提取 2–5 个中文关键词、项目简称和可能的同义词。
3. 优先搜索整理后的知识与正式记忆：

   ```bash
   rg -n -i --glob '*.md' --glob '*.txt' -- \
     '关键词1|关键词2|同义词' knowledge/imports memory digest PROFILE.md
   ```

4. 命中后读取相关文件的上下文，不要只凭单行片段下结论。
5. 如果整理区没有命中，再按需搜索原始归档：

   ```bash
   rg -n -i --glob '*.md' --glob '*.txt' -- \
     '关键词1|关键词2|同义词' knowledge/archive
   ```

6. 多个来源冲突时，优先采用日期更新、用户明确确认、来源更直接的记录；
   无法判断时把冲突告诉用户。
7. 在涉及历史事实的回答结尾标注相对来源，例如
   `【知识库：knowledge/imports/.../projects/growth_platform.md】`。

没有检索到依据时明确说“本地知识库暂未检索到”，不要把模型推断冒充为
历史记忆。

## 写入长期记忆

只记录以下内容：

- 用户明确要求“记住”的内容；
- 用户明确确认的稳定偏好、个人事实和工作规则；
- 已经形成结论的重要决策、责任边界和后续行动；
- 在多项任务中可复用的方法和标准。

将新候选内容追加到 `memory/inbox/YYYY-MM-DD.md`。每条至少包含：

- 时间；
- 类型：事实、偏好、决策、标准或待办；
- 内容；
- 来源会话或文件；
- 状态：待确认或已确认。

不要写入密码、Token、API Key、SSH Key、身份证号、银行卡号等敏感凭据。
不要把临时任务、未经确认的推断、长段聊天原文写成长期记忆。

## 更正与删除

用户要求更正记忆时，保留变更时间和更正原因，避免静默覆盖造成来源丢失。
用户要求删除时，先明确目标文件和内容；知识、记忆和原始归档属于重要数据，
删除前必须再次确认并保留可恢复备份。
