# Jarvis V1 验收清单

## 基础可用性

- [ ] 容器状态为 `healthy`
- [ ] Web 控制台必须登录后才能访问
- [ ] `codex --version` 正常，`codex login status` 显示 ChatGPT 登录
- [ ] `backend=codex`，无需 OpenAI API Key
- [ ] 控制台普通对话正常，页面不再以 `free` 模型承担主链请求
- [ ] 容器重启后配置和对话仍存在

## 钉钉入口

- [ ] 文本消息可以正常回复
- [ ] 连续三轮对话上下文正确
- [ ] 图片能够被接收和理解
- [ ] Word、PDF 或 PPT 文件能够被接收
- [ ] 长回复格式可读，不出现重复发送
- [ ] 同一钉钉消息重试不会产生重复任务

## 记忆

- [ ] 能识别用户称呼为“焦书记”
- [ ] 新会话能按需检索已确认的长期记忆
- [ ] 用户明确要求核验时，能说明历史知识的依据
- [ ] 普通回答不暴露知识库路径、文件名、行号、记忆 ID 和 Skill 名称
- [ ] 只有明确要求核验来源时才说明依据，且业务回答使用自然语言描述
- [ ] 临时信息不会被错误写成长期事实
- [ ] 普通候选进入 `memory/inbox`，明确“记住”进入 `memory/curated`
- [ ] 每轮只提取稳定候选，不保存寒暄、临时要求、整段聊天或模型最终答复
- [ ] 同一轮多个候选可一次收口；任一候选含敏感信息时整批不写入
- [ ] 重复写入保持幂等，不产生相同记忆副本
- [ ] 更正记忆后旧版本保留为 `superseded`，当前视图只显示新版本
- [ ] `./scripts/memory-status.sh` 能校验账本并重建当前视图
- [ ] 备份后可检查到 memory、sessions 和 workspace 文件
- [ ] OAuth 凭据目录已备份且未进入 Git

## 工作材料闭环

- [ ] 钉钉上传的 Word、PDF、PPT、Excel、图片和文本能够被读取
- [ ] 明确要求纳入项目时，原件完成校验归档且重复上传不会生成副本
- [ ] 会议纪要区分结论、共识、建议和行动项，不猜测责任人及时间
- [ ] “高层汇报版”默认一页、结论先行、只保留三个重点
- [ ] 项目决策、行动项、里程碑、进展和风险进入各自当前视图
- [ ] 材料内容与指定项目明显冲突时先确认，不把业务材料写入 Jarvis 台账
- [ ] 错误项目条目通过追加式迁移纠偏，源历史保留且当前视图不再串项
- [ ] 行动项状态变化保留历史，不覆盖原始记录
- [ ] 新会话可以自然回答项目最近结论、风险和待办
- [ ] 普通回复不暴露路径、材料哈希、条目 ID 和 Skill 名称
- [ ] `./scripts/workflow-status.sh` 返回 `workspace_workflows=verified`

## 钉钉表达

- [ ] 简单问题自然简洁，不机械增加四段标题和 Emoji
- [ ] 项目进展按当前状态、已完成、风险和下一步清晰分区
- [ ] Emoji 只表达约定语义，不用完成标记包装计划事项
- [ ] 没有可靠分子和分母时不生成进度百分比
- [ ] 高层版只保留核心结论、三个重点和需要决策的事项
- [ ] 用户要求纯文本或正式公文时自动关闭 Emoji
- [ ] 不使用钉钉不稳定支持的 Mermaid、HTML 和复杂嵌套表格

## 订阅与 Codex

- [ ] 容器重启后无需重新登录 ChatGPT
- [ ] 能在工作区创建测试文件并读取结果
- [ ] 高风险命令会进入审批，不会静默越权执行
- [ ] 钉钉只显示最终回答，不显示 reasoning 和冗长工具轨迹
- [ ] `./scripts/codex-status.sh` 显示 `turn_recovery_patch=installed`
- [ ] 长任务执行期间重启容器后，旧 `Thinking` 状态被撤回并收到明确中断通知
- [ ] 重启恢复通知不包含原始问题、模型输出或内部存储路径
- [ ] 旧系统 Current Turn Guard、中断恢复和重启通知只有完成当前运行链路的等价回归后，才能标记为已具备
- [ ] 达到订阅限额时能明确报告，不自动降级到未知付费 API

## 安全边界

- [ ] 控制台仅监听 `127.0.0.1`
- [ ] `./scripts/check-proxy.sh` 三项连通性检查不返回 `failed`
- [ ] 使用 host 网络时，`ss -lntp` 中 8088 仍只绑定 `127.0.0.1`
- [ ] `.env`、secrets 和 runtime 未进入 Git
- [ ] 容器未挂载 Docker Socket 和宿主机敏感目录
- [ ] Codex 为 `sandbox=danger-full-access`，权限仅存在于受限 Docker 容器内
- [ ] Tool Guard、File Guard 已启用
- [ ] Skill Scanner 为 `block`
- [ ] Jarvis 拒绝执行 sudo、重启宿主机和修改自身运行配置
- [ ] `runtime/codex`、`runtime/secrets` 权限为仅部署用户可访问
- [ ] 未修改 Mihomo 配置、订阅地址和既有主备线路选择

## 切换条件

只有以上核心用例通过，且旧知识备份、迁移数量校验和恢复演练完成后，才允许将钉钉正式入口切到新 Jarvis。旧服务器最后退役。
